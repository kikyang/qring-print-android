# 协议逆向笔记

> **2026-08-10 更新**：协议已由开源项目 [Thisko/QrintPrint](https://github.com/Thisko/QrintPrint)（MIT）逆向并真机验证。本文档为完整协议整理（来源：`reference/qrintprint/QringProtocol.ets` + `PrinterConnection.ets`）。实物到位后需实测核对。

## 设备信息

- 品牌：错题小印（Qring / BeePrt BY 系列）58mm 蓝牙热敏打印机
- 打印头：384 点宽（203dpi），每行 48 字节，无补位
- 蓝牙：**经典蓝牙 SPP + BLE 双模**（SPP 已验证；BLE 通道待开发验证）
  - 2026-08-11 修正：X1 SPP 为**单向**（能打印、查询无响应，真机验证）；BLE 透传全功能
- SPP UUID：`00001101-0000-1000-8000-00805f9b34fb`（标准 SPP RFCOMM），secure 配对
- 设备名带 `Qring` 前缀（PrinterDiscovery 默认过滤规则）

## 协议总览

**非标准 ESC/POS**：状态查询、电量、浓度走私有 `10 FF` 系列命令；仅走纸（`ESC J`）和光栅位图（`GS v 0`）沿用标准 ESC/POS。

## 指令表（Hex）

| 命令 | 字节 | 说明 |
|---|---|---|
| CMD_ENABLE | `10 FF F1 02` | 打印使能 |
| CMD_ENABLE2 | `1F B2 10` | 打印使能（第二段） |
| CMD_STOP | `10 FF F1 45` | 停止打印 |
| CMD_WAKEUP | `00 ×12` | 唤醒（12 个 0x00） |
| CMD_STATUS | `10 FF 40` | 查状态，响应 1 字节 |
| CMD_BATTERY | `10 FF 50 F1` | 查电量，响应 2 字节（**第 2 字节 = 百分比**） |
| CMD_MODEL | `10 FF 20 F0` | 查型号，响应 ASCII 字符串 |
| CMD_FW_VERSION | `10 FF 20 F1` | 查固件版本，响应 ASCII |
| CMD_SN | `10 FF 20 F2` | 查序列号 |
| CMD_BT_NAME | `10 FF 30 11` | 查蓝牙名 |
| 浓度 | `10 FF 10 00 <level>` | 打印浓度/加热强度（APP 文字用 1） |
| 自动关机 | `10 FF 12 <秒高> <秒低>` | 大端 16 位，单位秒 |
| 走纸 | `1B 4A n` | ESC J n 点行（n>255 需拆多条） |
| 光栅头 | `1D 76 30 m wL wH hL hH` | GS v 0，m=0~3，数据紧跟发送 |

## 状态字节（响应 1 字节，0x00 = 一切正常）

| 位 | 值 | 含义 |
|---|---|---|
| 0 | 0x01 | 打印中 |
| 1 | 0x02 | 开盖 |
| 2 | 0x04 | 缺纸 |
| 3 | 0x08 | 低电压 |
| 4 | 0x10 | 过热 |

注意：开盖时纸传感器会同时置缺纸位，判断顺序必须是 **开盖 → 缺纸 → 过热**。

## 主动上报（FF xx）

- 打印完成 ACK：`0xAA`
- 故障帧：`FF <code>`，code：01=缺纸 / 02=开盖 / 03=过热 / 04=低电量

## 连接与查询时序（照搬 QringPrint 验证过的行为）

- **查询固定套路**：清空接收缓冲 → 发命令 → 等 150ms → 读响应（超时 1500ms）
- **分包**：每 1024 字节一包，包间 1ms
- **状态轮询**：间隔 10s；**打印期间停止轮询**（避免查询字节混入打印数据流）

## 打印时序（完整流程）

```
1. CMD_ENABLE → CMD_ENABLE2
2. cmdThickness(level)      # 可选，文字用 1
3. CMD_WAKEUP (12×0x00)
4. 前走纸 FEED_BEFORE = 10 点行
5. GS v 0 头 + 光栅数据    # 384 点宽，48 字节/行，MSB first，置 1 = 黑
6. 后走纸 FEED_AFTER = 100 点行
7. CMD_STOP
8. 等 ACK 0xAA（超时 120s，同时盯 FF xx 故障帧）
```

打印前建议现查一次状态（preflight），有故障直接拦截（开盖 > 缺纸 > 过热）。

## 光栅编码（RasterEncoder 要点）

- 宽度固定 384 点；图片按比例缩放到 384 宽，高度任意
- 每行 48 字节；位序 MSB first，**置 1 = 黑点**
- 灰度 → 二值化阈值：文字 212 / 条码 128（不抖动）/ 图片可选抖动（Floyd-Steinberg / Ordered / Bayer）

## X1 实测补充（2026-08-11 电脑端 BLE 实测）

**设备信息 `10 FF 70`（X1 特有，QrintPrint 无此命令）**：响应 67 字节 ASCII：
`Qring_B8EA|65:56:10:28:B8:EA|65:56:10:28:B8:EA|V1.05|X1012100842|16`
字段顺序：名称 | MAC | MAC | **固件版本(V1.05)** | SN | 电量(15→16 动态变化)

**固件版本查询结论**：
- `10 FF 31`（及 31 00 / 31 F1 / 31 30 / 31 01 全部变体）**X1 无响应** —— 勿用
- `10 FF 20 F1` 返回 `V1.05` = 固件版本（与 10 FF 70 第 4 段一致）
- `10 FF 20 F0` → `X1`（型号）；`10 FF 20 F2` → SN
- 安卓端 queryDeviceInfo() 已改为：10 FF 70 一次解析（名称/固件），兜底 10 FF 20 F0/F1

**光栅 mode 双通道定稿（2026-08-11 实测）**：
- **文字：m=0**——用户实测文字本来就黑（不需要加深），不变形
- **图片：行合并减半 + m=2**——m=2 是标准"双倍高"（垂直复制，直接打会纵向拉长 2 倍，用户实测确认）；
  解法：数据行每 2 行 OR 合并成 1 行（RasterEncoder.halveRows，1px 细线不丢只变粗）→ 发 m=2
  → 打印高度 = (H/2)×2 = H 还原，黑度靠每行加热两遍提升。实测：比例正常、黑度保持、预览一致 ✅
- m=2/3 含 0x00 数据安全（m=1 有 00 bug，勿用）；m=3 双倍宽有超 384 点打印头风险，不用
- 预览：图片 = halveRows 后 verticalScale=2 渲染（模拟 m=2）；文字 = 1:1
- 光栅分块：64 行数据/块（=128 物理行）保守安全
- **无预热条**：用户实测排除——文字不打预热本来就黑，全黑块打不打预热都不黑（固件电流限制）；
  预热条还引入"顶部 1/8 白黑条"怪象（光栅头紧跟 ESC@ 被文本引擎吞字节）
