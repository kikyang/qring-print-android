# 统一准备打印页 · 设计方案（#23 + #24）

> 建立 2026-09-28。证据全部来自当前代码（Android v0.7.7，`MainActivity.kt` 4305 行），未做推断。
> 待办出处：`docs\待办事项清单.md` #23「统一准备打印页 + 统一打印确认条」、#24「模板系统改为生成器」。
> 交互路径出处：待办清单「下一版统一交互路径（2026-08-18 已确认）」。

## 一、现状（代码实测）

### 1.1 打印页结构

`buildPrintPage()`（`MainActivity.kt:677`）= 顶部 5 个二级 Tab：
**文字 / 图片 / 条码 / 文档 / 其它**，每个 Tab 是**一整个长表单**（参数 → 预览 → 打印按钮），
由 `visibility` 切换（`MainActivity.kt:721-734`）。

### 1.2 各路径的"打印"行为**并不统一**

| 路径 | 预览在哪 | 打印按钮 | 点下去发生什么 |
|---|---|---|---|
| 文字 | 页内嵌 `Image`（`buildTextContent:786`） | 「🖨 打印文字」`doPrintText` | **需先手点「👁 预览打印效果」**才渲染预览 → 再弹确认框 |
| 图片 | 全屏实时预览（工作台） | 顶栏「🖨 打印」`doPrintImage` | 直接弹确认框 |
| 条码 | 页内嵌预览（`renderBarcodePreview`） | `doPrintBarcode` | 直接弹确认框 |
| 文档 | 页内嵌预览（`renderDocPreview`） | 「🖨 打印文档」`doPrintDoc` | 直接弹确认框 |
| 模板（其它 Tab 宫格） | **无页内预览** | 点宫格即动作 | `printTemplate { gen() }` → **直接弹确认框** |
| 函数图像 / 批量 / 口算 | 各自独立弹窗（`showFunctionGraphDialog` / `showBatchDialog` / `showMathDialog`） | 弹窗内按钮 | 各自路径 |

**结论（针对 #23）**：**「统一打印确认条」已经在 v0.7.4 完成** —— 所有路径最终都走
`previewConfirmDialog()`（`MainActivity.kt:3203`，份数 1~10 / 浓度 淡中浓 / 前后走纸 无·1段·2段，
且 v0.7.6 已按 issue #5 加 ScrollView + 预览图高度自适应）。

**真正没统一的是「准备页」这一层**：

1. **预览与确认条分家**：预览画在页内嵌区（或干脆没有），确认条在弹窗里 → 用户"看到的效果"和"要确认的东西"不在同一屏。
2. **入口行为不一致**：文字要手点一次「预览打印效果」；模板类连预览都没有，点宫格直接跳弹窗。
3. **参数与确认条分居两处**：浓度/走纸在弹窗里，内容参数（字号/对齐/抖动…）在页内，用户改浓度得在弹窗里改、关掉弹窗再想改内容就回到页内 → 两处来回。
4. **模板生成结果无处可调**：`printTemplate { TemplateLibrary.courseTable() }` 生成位图后**直接进确认框**，
   想改浓度是有的（确认条里有），但**没有"生成后先看一眼大图再决定"**的中间态。

### 1.3 #24「模板改生成器」的实际进度

- **已经是生成器**：`SystemTemplates`（内置 JSON 注册表）+ `runSystemTemplate()`（`:1258`）分发 8 个入口；
  生成即进图片通道。新课只需加一行 JSON。
- **未兑现的部分**：生成结果**没有回到"统一流程"的中间层**，而是各自弹窗/直接确认。
  即：**"生成器"这半做完了，"回统一准备页"这半没有。**

## 二、方案对比

### 方案 A（推荐）：**保留 5 个 Tab，抽出「准备打印页」这一层**

- 新增全屏 `PreparePrintView`（**不新增 Activity**，与现有页内切换一致，避免主题/状态重建）：
  - 上半：大预览（`imagePreviewRaster()` 由**待发送的 1-bit 光栅**直出 → 真·所见即所打，v0.7.2 已有该函数）
  - 中部：**内容相关操作**（按来源类型给不同按钮，如文字→「改字号/对齐 返回」；模板→「换个模板」）
  - 下部：**统一确认条**（把 `previewConfirmDialog` 里那套浓度/前后走纸/份数**原样搬进来**，代码复用同一构造器）
  - 底部：「🖨 打印」+「← 返回修改」
- 所有路径终点从"弹 `previewConfirmDialog`"改为"`goPrepare(raster, 来源)`"：
  文字 / 图片 / 条码 / 文档 / 模板 / 画布 / 错题卡 共 7 条。
- 各 Tab 内的「打印」按钮文案改为「下一步：准备打印 →」（行为=校验参数 → 渲染 → 进准备页）。
- **风险**：低。`doPrintConfirmed()`（`:3306`）不动（仍是最终执行者，只把调用者从弹窗按钮换成准备页按钮）。
- **测试影响**：`MainActivityUiTest`（20 例）中与确认对话框相关的 1~2 例需改为断言准备页；
  `previewConfirmDialog` 若保留（供"快速打印"用）则测试可不动。

### 方案 B：**按 2026-08-18 已确认路径重排入口**（改动大）

打印页顶部不再直出表单，改为 4 个入口卡：

```
快速通道：文字 / 条码 / 文档
图片工作台：图片 / 错题卡 / 拍照 / 分享 / 手动裁剪
模板：一键生成 → 回统一流程
自由设计：画布 → 回统一流程
```

- 需把**错题卡从「其它」移进图片工作台**（8-18 路径如此，但 v0.7.4 的 #8 已把它并入模板宫格 → **两处决议冲突**）；
- 画布从图片页内置入口升为独立「自由设计」入口；
- **风险**：中高。动 5 Tab 结构 + 移错题卡/画布入口，UI 测试要大改（`五个二级Tab的图标文件都存在`、
  `启动后三Tab与功能块构建成功` 等结构性断言），用户熟悉的入口位置全变。

### 方案 C（最小步）：只把"预览"统一，不新增页面

各 Tab 的「打印」按钮统一为"先渲染预览 → 再点一次确认"。改动最小，
但**没解决"预览与确认条分家"**，等于只做了一半 #23 → 不建议。

## 三、推荐路线

**先 A，后 B**：

1. **第一步（本版）**：做方案 A —— 把"准备页"这层立起来，7 条路径全部汇聚；模板生成后**先进准备页**（#24 的后半）。
2. **第二步（下一版，可选）**：在准备页稳定的基础上再做 B 的入口重排 —— 那时只需改 `buildPrintPage` 的入口层，
   准备页与各工作区**不必再动**，风险被 A 吸收掉了。

理由：A 与 B **不冲突**，A 是 B 的地基；先 A 能用最小回归面拿到 #23 的主体收益。

| D2 | 错题卡归属：留在**模板宫格**（v0.7.4 现状）vs 移进**图片工作台**（8-18 路径） | 两处历史决议冲突，须择一 |

## 五、验收判据（拟）

1. **七条路径全部经准备页**：文字 / 图片 / 条码 / 文档 / 模板 / 画布 / 错题卡 —— 单测断言入口调用 `goPrepare`（可用注入计数器）。
2. **准备页与打印结果一致**：准备页显示的位图由**待发送光栅**直出（复用 `imagePreviewRaster`），
   断言 `preparePreview == imagePreviewRaster(待发送 raster)`。
3. **确认条不被挤出屏幕**（issue #5 防回归）：准备页在最小屏高下「🖨 打印」按钮仍可见。
4. **批量打印**：准备页标题显示"共 N 条"，确认后 `doBatchPrint` 按 N 条执行（现有 35 例 E2E 不回归）。
5. 全量测试（现有 210 例 + 新增）全过；R8 体积不显著增长（当前 1.03MB）。

## 六、实施结果（2026-09-28，方案 A 已落地）

用户拍板：**路线 = 先 A 再 B**；准备页 = 全屏页内视图；批量 = 首条预览 + 总数；错题卡 = 留在模板宫格（现状）。

### 6.1 改了什么（`MainActivity.kt`）

- 新增第 6 块页内视图 `prepareContent`（`buildPrepareContent()`）：大预览 + 内容相关操作 + 「打印设置」卡（
  `prepareBarHolder`）+「🖨 打印」主按钮 + 状态行。
- 新增 `goPrepare(title, sub, preview, backLabel, onPrint)` —— **所有打印路径的唯一终点**；
  `backToWorkspace()` / `isPrepareShowing()` / `preparePreviewMaxHeight()` 配套。
- 把确认条从 `previewConfirmDialog` 里抽出为 `buildConfirmBar(): ConfirmBar`，**两条入口共用同一构造器**，
  浓度/前走纸/后走纸/份数逻辑逐字未改 → 不会漂移。
- **11 处调用点**改走 `goPrepare`：文档 / 条码 / 文字 / 图片 / Markdown / 重做卷 / 错题卡 / 模板（课程表·单词表·
  每日计划·口算题，`printTemplate(name, gen)`）/ 函数图像 / 自检页 / 批量。
- 批量：新增 `batchFirstPreview()`，弹窗确定 → 校验首条可渲染 → 进准备页（标题「共 N 条」）→ 确认后整批连打。
- 按钮文案统一为「下一步：准备打印 →」（5 处）；返回键在准备页时回工作区（`onBackPressed`）。
- 模板类入口先 `dismiss` 卡片弹窗再进准备页，避免弹窗压住准备页。

### 6.2 测试抓到的一个**真 bug**（已修）

新增用例 `准备页返回按钮回到原工作区` 首跑失败：返回后工作区表单仍不可见。根因——
`RadioGroup.check()` 对**已选中**的项**不触发** `OnCheckedChangeListener`，而返回时恰好是"切回原 Tab"，
可见性切换逻辑只写在监听器里 → 6 块内容停在 GONE。修法：把可见性逻辑抽成 `applyPrintSubTab(id)`，
监听器与 `backToWorkspace()` 都调用（显式重放）。
